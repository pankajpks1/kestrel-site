Data pipelines

Export your events, user profiles and identity mappings to your own cloud storage every day, as files you can load anywhere.

A data pipeline writes your project's data to a bucket you own, on a schedule, so you can load it into your warehouse or process it with your own tools. Kestrel can export to Amazon S3, Google Cloud Storage and Microsoft Azure Blob Storage. Open Data › Destinations, find the pipelines in the library and pick your storage.

Create a pipeline

  1. Fill in the storage's form.
    • Amazon S3: the bucket, the region, the encryption (none, AES or KMS, with an optional KMS key ID) and the role Kestrel assumes to write to the bucket. The role's trust policy must name Kestrel's export identity and require your project token as the external ID.
    • Google Cloud Storage: the bucket and its region.
    • Azure Blob Storage: the client ID, client secret and tenant ID of a service principal, the storage account and the container name.
  2. Choose the Data Source: events, user profiles (people) or identity mappings. Create one pipeline per data source.
  3. Under Advanced, set Backfill From (events only; up to 6 months back) and the Frequency (daily or hourly).
  4. Choose Create.

With Trial on (the default) the pipeline exports daily and backfills at most one day. Turn it off to keep exporting beyond the trial; the Data Pipelines add-on is needed for that.

Secrets are stored sealed and are never shown again.

When it runs

A day is a day in the project's time zone. A daily pipeline exports each finished day at 30 minutes past midnight. An hourly pipeline also re-exports the current day at 30 minutes past every hour. People and identity mappings are exported whole each time, not by day. A failed export is tried again an hour later. The pipeline's page shows each day's status and any error.

File layout

Every file is gzipped JSON, one object per line, up to 100,000 rows per file. Within your bucket, under your project ID:

DataPath
Events<project id>/mp_master_event/<yyyy>/<mm>/<dd>/…json.gz
User profiles<project id>/mp_people_data/…json.gz
Identity mappings<project id>/mp_identity_mappings_data/…json.gz

Re-running a day replaces it: Kestrel writes the new files first and then deletes the day's older ones, so each event is in its day exactly once.

Schema

DataFields
Eventsevent_name, time (Unix seconds, UTC), distinct_id, device_id, user_id, insert_id, properties (every property of the event)
User profilesdistinct_id, properties
Identity mappingsdistinct_id, resolved_distinct_id

Use insert_id to remove duplicates if you load the same day twice.

Limits

  • A backfill can start at most 6 months ago, and only for events.
  • A trial pipeline exports daily only.
