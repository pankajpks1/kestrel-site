Setting up Kestrel

Send your first events, check they arrive, and open a board built on them.

The Set Up Guide takes a new project from nothing to its first board in four steps. Open it any time from the gear menu: Set Up Kestrel. Your project token is at the bottom of the guide's left panel, with a button to copy it — every way of sending data needs it.

1. Get started

Choose how your data will reach Kestrel:

  • Use your Coding Agent — the guide gives you a prompt to paste into your coding assistant, in your project's folder. It names the SDK to install, your token and your Kestrel address, and asks the assistant to identify signed-in users and track your key actions.
  • Quick Start — add Kestrel's SDK to your website or app yourself. Most teams start here.
  • I already collect data in a tool — send events from your servers, or bring your history over, through Kestrel's HTTP APIs (below).

If someone else on your team should do this part, use Invite a Teammate.

2. Connect your data

With an SDK

Pick your platform with Select a different SDK:

PlatformHow it installs
Javascript (websites)An HTML snippet, or the @rivero/kestrel-browser package from npm or yarn.
Android (Kotlin)Gradle.
iOS (Swift)Swift Package Manager.

For websites, two switches shape the code before you copy it:

  • Autocapture (on by default) records page views, clicks, scrolling and form activity without any tracking code.
  • Session Replay records visits so you can watch them back — see Session Replay.

Under Track your key actions you'll find the two calls worth adding next: identify, once a person signs in, so their events join up across devices; and track, for the moments that matter to you, such as a plan upgrade.

From your servers or another tool

Kestrel accepts events over two HTTP APIs, each authenticated with your project token as the username:

  • /import for historical events, each with its own time. Give every event an $insert_id: a batch sent twice is then counted once.
  • /v1/batch for a live stream of track, identify and group calls in the widely used Segment format.

The guide shows a ready-to-run example of each, with your address and token filled in.

With your coding agent

Copy the prompt and paste it into the assistant. Review its changes as you would any pull request before you ship them.

3. Verify the connection

Open your site or app so it sends something. The guide checks every few seconds and ticks off Events, Users and Replays as each arrives; when the first event is in, it shows Connection verified!

Nothing showing up after a minute? Check that the token and address in your code match the ones in the guide, and that a content blocker isn't stopping the script in your browser.

4. Explore your data

The last step offers board templates: pick one and Kestrel builds a board of reports on your own events, asking only which of your events to use. You can open the guide again later to add another platform.
