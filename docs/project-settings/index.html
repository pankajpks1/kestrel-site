Project settings

Time period settings that shape your charts, and how Identity Merge joins a person's events.

Project settings apply to everyone in the project. Admins can change them in Project Settings › Overview.

Time period settings

SettingDefaultWhat it affects
Start of WeekMondayWhere each week begins when a report is shown by week.
Start of QuarterJanuaryWhere each quarter begins when a report is shown by quarter.
Start of WeekendSaturdayThe first day of your weekend.
Duration of Weekend2 daysHow many days your weekend lasts, from 1 to 6.

All of these follow the project's time zone.

Weekends

Many products behave differently at the weekend, and the dips can hide the trend you are looking for. The weekend you set here is used by the Weekends chart option:

  • In an Insights report's chart options, set X-Axis › Weekends to Hidden to leave weekend days out of a line chart. The gap is drawn as a narrow break so the line stays readable.
  • You can also click a point on the chart and choose Hide Weekends or Show Weekends.
  • The option applies when the chart is shown by day. Weekends are visible by default.

Set the weekend to match your market — for example Friday and Saturday where that is the local weekend.

Identity Merge

People use your product before they sign in, and often on more than one device. Identity Merge joins those visits into one person, so a report counts them once and a funnel follows them from their first visit to their purchase. Kestrel offers two ID Merge APIs; you can see which one your project uses in Project Settings › Identity Merge.

The API is chosen before any data arrives: in a new project, an Admin can switch between the two there. Once the first event has arrived it is fixed, because changing it would regroup the events already counted. Organization admins set the API new projects start with in Organization Settings › Identity Merge.

Simplified vs. Original ID Merge

Simplified API (the default)Original API
What joins a person's idsAny event that carries both a device id ($device_id) and a user id ($user_id).Only the special $identify, $create_alias and $merge events.
Anonymous eventsAll of a device's anonymous events, before and after sign-in, join the user it is seen with.Join when identify links the device to the user.
Two signed-in usersNever merged: a user id always stays its own person.Can be merged by $merge or alias.
LimitNo limit on a person's devices.Up to 500 ids in one person.

Choose the Simplified API unless your tracking already relies on alias or $merge — for example when you bring a project over from another tool that used them.

Key changes from the Original API

  • No special events. Signing in is just your SDK's identify(userId); it adds the user id to the events that follow, and the device and user are joined from there.
  • alias and $merge don't join people. Under the Simplified API they are kept as ordinary events.
  • A shared device follows its latest user. If two people sign in on one device without your app calling reset() at sign-out, the device's anonymous events go to the user it was seen with last. Call reset() when someone signs out.
  • The distinct id is derived. An event's distinct id is its user id when it has one, otherwise its device id.
