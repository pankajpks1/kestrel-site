MCP (Model Context Protocol) is the common way AI assistants connect to other products. Kestrel speaks it in both directions:

  • Kestrel in your assistant — ask Claude, ChatGPT, Cursor or any assistant that supports MCP about your product data, and get Kestrel's exact numbers and charts back in the conversation.
  • MCP Connections — let Kestrel's own Agent read from other tools you use.

Kestrel in your assistant

Kestrel's MCP server lives on your query address, at the path /mcp: for example https://api.your-company.kestrel.rivero.co.in/mcp.

Connecting

  1. In your assistant, add a custom connector (in Claude: Settings › Connectors › Add custom connector). Name it Kestrel and give it the address above.
  2. Choose Connect. A Kestrel page opens: sign in if asked, read the card describing what the assistant may do, and choose Authorize.
  3. Back in the assistant, ask something like "How did sign-ups do last week compared with the week before?"

The connection acts as you, with your role in the project: it sees what you can see in Kestrel and nothing more. Signing out of Kestrel, or being removed from the organisation, ends it straight away.

For scripts and assistants without sign-in support, use a service account instead: Organization Settings › Service Accounts › Add Service Account gives a username and secret (shown once), sent as HTTP Basic credentials. Every call is held to the account's role and shows in the Audit Log with the origin MCP.

If your Kestrel address only accepts some networks, the assistant's servers must be allowed to reach /mcp; ask whoever runs your Kestrel deployment.

What it can answer

Ask aboutWhat Kestrel returns
An overviewHow fresh the data is, the last 7 days against the 7 before, the top events and their change, your boards.
What's trackedEvents with their 30-day counts, properties to filter and break down by, and their values.
TrendsUp to 10 metrics over time — events, unique users, sessions, sums and averages of a property — with breakdowns, filters, cohorts and a comparison with the previous period.
Funnels, retention and pathsStep conversion and drop-off with time to convert; retention by cohort with its curve; the most common journeys before or after an event.
Why a number movedThe segments that explain a change on a given day.
Boards, cohorts and peopleAny board's charts for any date range; your cohorts; one user's profile.
Anything elseRead-only SQL over your events, with the same limits as the SQL explorer.

Every answer comes from the same code that draws Kestrel's reports, so it matches what you would see in the app, to the last digit. Assistants that can display them show charts in the conversation, each with Open in Kestrel to continue in the full report. Date ranges are read in your project's time zone.

The one thing an assistant can change is to create a board from its findings, which is private to you unless you ask otherwise. It cannot edit or delete anything.

MCP Connections

Kestrel's Agent can read from other tools — your issue tracker, your docs — through their MCP servers, to bring that context into its answers.

  1. An Organisation Owner or Admin turns on Enable MCP Connectors under Organization Settings › AI Settings. It is off by default; while it is off nobody can add a connection and the Agent uses none.
  2. Each person then adds their own under Settings › Profile › MCP Connections › Add Connection: a name and the server's address. Kestrel checks the server, and asks for an authentication token if the server needs one.

Connections are read-only and private to you: teammates cannot see or use them, and the Agent uses only the connections of the person asking. Remove one with its trash icon at any time, even while connectors are turned off. Servers that sign in only through a browser (OAuth) can't be added yet; if such a server also takes a personal access token, paste that instead.
