A session is one stretch of a user's activity. Kestrel builds sessions from the events you already send — there is nothing extra to track — and uses them for the Total Sessions measurement, the Session Start and Session End events, and session properties in every report.

Admins change the definition in Project Settings › Session Settings.

Definition types

TypeA new session starts when…
Timeout Based (default)The user has been inactive for longer than the timeout. The default is 30 minutes; you can set anything from 1 minute to 24 hours.
Event BasedThe user does your Session Start Event; the session ends at your Session End Event.
Property BasedThe value of your Session ID Property changes — use this if your app already assigns session IDs.

Whatever the type, every session ends at midnight in the project's time zone, so a session never spans two days.

Excluded events

Some events shouldn't keep a session alive — background syncs, push notifications received. Add up to 500 Excluded Events; they are ignored when sessions are built. Kestrel's own bookkeeping events (such as identity merges) and events hidden in Lexicon are always excluded.

Session properties

Every session carries these properties, which you can filter and break down by:

  • Session Duration (Seconds) — from the session's first event to its last.
  • Session Event Count — how many events it holds, not counting excluded or hidden events.
  • Session Start Event Name and Session End Event Name.

Session Start and Session End also carry common properties from the session's events — browser, device, operating system, city and country, app version, current URL, and UTM source, campaign and content — so you can break sessions down by them. Add up to 4 more event properties to carry under Session Properties. Session-scoped custom properties are also created here.

After a change

Changing the definition recalculates sessions for all your history. Until that finishes, reports keep using the previous sessions.
